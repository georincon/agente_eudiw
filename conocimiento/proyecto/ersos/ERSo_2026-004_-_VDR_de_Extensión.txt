1. Contexto y objetivo
Este informe documenta la ejecución del ERSo 2026-004 — Despliegue del registro
verificable de datos (VDR) de extensión, del proyecto Identidad Digital Soberana SSI,
sobre el repositorio av-app-android-wallet-ui (fork del eudi-app-android-wallet-ui
de la UE).

El ERSo exige habilitar, de forma opcional y sin afectar el camino base, un registro
verificable de datos que soporte la publicación de DID Documents, con estas
capacidades: exponer endpoints de registro, adaptar la forma del registro al método DID
empleado, registrar/actualizar entradas, y respaldar/recuperar el estado del registro.

Solución construida: el módulo vdr-extension-logic , un servicio standalone
(Kotlin/JVM, servidor Ktor embebido) que guarda cada DID Document en un repositorio
Git local — cada registro/actualización es un commit, lo que da trazabilidad y
respaldo/restauración sin infraestructura adicional — y que, por construcción de módulos
de Gradle, no tiene ningún camino de dependencia hacia la app ni el APK.

Este documento cubre, en orden: cómo se implementó el proceso, el manual paso a paso
para ejecutarlo, y la evidencia real de ejecución mapeada a cada uno de los 3 criterios de
aceptación del ERSo.


2. Descripción del proceso implementado
Se creó vdr-extension-logic como módulo Kotlin/JVM puro (convención
 project.jvm.library , ya existía en el repo sin uso). A diferencia de los módulos Android
del proyecto, este tipo de módulo no registra la extensión moduleConfig{} y por lo tanto
no puede entrar al enum LibraryModule ni a assembly-logic — el único lugar por el que
un módulo llega a :app .

topología de módulos Gradle · vdr-extension-logic sin conexión al APK

La flecha nunca llega a vdr-extension-logic porque, estructuralmente, no hay ninguna
línea de código en assembly-logic ni en :app que lo mencione.


Cómo se guarda y versiona el registro
Cada DID Document se guarda como un archivo dentro de un repositorio Git local ( vdr-
data/registry/ ). Cada operación de registrar o actualizar es un commit: el git log de
ese repositorio es la trazabilidad que exige el criterio de aceptación #1, sin necesidad de
una base de datos adicional. El respaldo empaqueta ese mismo repositorio en un git
bundle ; la restauración reconstruye el repositorio desde un bundle guardado.

3. Manual paso a paso de ejecución
Requisito previo: el módulo está apagado por defecto. Se activa solo para la sesión de
terminal actual, sin modificar archivos, con el flag -PvdrExtension.enabled=true .


3.1 Levantar el servicio (terminal 1)

  cd /home/geovani/Workspace/Wallet/av-app-android-wallet-ui
  ./gradlew -PvdrExtension.enabled=true :vdr-extension-logic:run


Esperar el mensaje Responding at http://0.0.0.0:8089 . Dejar la terminal abierta.

Nota de ruta: Gradle ejecuta el proceso usando la carpeta del propio módulo como
directorio de trabajo. Los datos quedan en:

  av-app-android-wallet-ui/vdr-extension-logic/vdr-data/registry/
  av-app-android-wallet-ui/vdr-extension-logic/vdr-data/backups/

3.3 Apagar
En la terminal 1: Ctrl+C . Al no pasar de nuevo el flag -PvdrExtension.enabled=true , el
módulo vuelve a estar completamente fuera del build.



4. Evidencia de ejecución real

logic:test , 11 de 11 exitosas) y la sesión manual real corrida por el equipo con curl .

Criterio 2 — Respaldo y recuperación
Automatizado: BackupRestoreTest (3 pruebas) — respaldar y restaurar deja el registro
idéntico al momento del backup; restaurar un backup inexistente falla con error claro;
 list() devuelve los backups creados.

Manual:

  $ curl -X POST http://localhost:8089/vdr/v1/backup
  {"backupId":"vdr-backup-1790629638002","path":".../vdr-data/backups/vdr-
  backup-1790629638002.bundle","createdAt":"2026-09-28T21:07:18Z"}

  $ curl -X POST http://localhost:8089/vdr/v1/restore -d '{"backupId":"EL-
  BACKUP-ID"}'
  {"error":"backup_not_found","detail":"No existe el backup 'EL-BACKUP-ID'"}


  $ curl -X POST http://localhost:8089/vdr/v1/restore -d '{"backupId":"vdr-
  backup-1790629638002"}'
  {"status":"restored","backupId":"vdr-backup-1790629638002"}

un error claro en vez de fallar silenciosamente.
